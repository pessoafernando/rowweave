# Documentation audit

This page is the working inventory for the documentation system. It records
what the `0.2.0` public preview documents today, the authoritative route for
each public behavior, and the maintenance instruction attached to each page.
Every row is `COVERED`: the open work is keeping pages synchronized with
source, not writing first drafts. It is a maintainer-facing map, not a claim
that every source-visible type is a supported extension point.

## Scope and method

The audit covers the eight Maven modules, the public capability contracts, the
0.2.0 approved API vocabulary, process entry points, connector contracts,
monitor routes, examples, configuration, limits, and stable refusals.

The approved API vocabulary is a narrower contract than source visibility: it
requires or retains 60 unique classes and approves 52 method signatures. The broader
set of 1121 source-visible public types needs an explicit boundary review so
that documentation does not accidentally promote an implementation type to a
supported extension point.

The curated Markdown inventory is regenerated by the documentation suite, so its
file, code-block and link totals appear in the output of a live gate run rather
than as a typed estimate. Every public behavior row below is now carried by an
authoritative page rather than a summary, so the open work is keeping those
pages synchronized with source rather than writing first drafts.

## Headline findings

* The public API inventory now traces all **60** unique classes in the frozen
  public vocabulary. The remaining documentation work is semantic coverage,
  not symbol discovery.
* Configuration has exact reader/documentation parity: **136** production reader
  keys, **11** concatenation families, and **155** documented property rows.
* The monitor dashboard, HTTP contract, Prometheus surface, and runtime views
  are the strongest current product documentation.
* Batch and Stream quickstarts, run modes, behavior contracts, and a tested
  example index exist. Function, expression, source, sink, executor SPI, schema,
  validation, incremental and durable-provider method contracts now each have a
  dedicated reference traced to declared source lines and qualifying tests.
* Method-level references now carry the Batch environment and execution contract
  and the Stream session, DataStream, state, time, checkpoint, savepoint, restart
  and rescale lifecycle, including serializer and output-tag binding rules.
* Stream lifecycle and stable refusals have a tested behavior reference; the
  unified error catalog covers 42 exception families, 28 coded families, and 555
  stable codes.
* Each supported connector and registry has a dedicated reference: resident CDC,
  the S3 snapshot connector, the PostgreSQL logical CDC connector, and the
  ZooKeeper service registry, each traced to provider contract, configuration,
  packaging, failure behavior and qualifying tests.
* Release, license, roadmap, and governance material exists. Support intake,
  vulnerability reporting, review boundaries, and candidate publication
  prerequisites are explicit; publication remains a separate owner action.
* Canonical pages are English and contain no non-Latin script. Comments in shipped
  Java sources and shipped resources are English too, and the source-language gate
  rejects a Chinese comment in CI, the documentation suite, and the release gate.
  The gate scans every tracked file, so test sources carry the same requirement.
* The repository-wide documentation suite is the single qualification entry
  point. The source anchor gate passes 973 code anchors and 41 test symbols:
  every cited line must be non-blank and must share an identifier with the
  sentence that cites it, and every referenced test class must exist.

overlap on `Collector`, so the unique public class vocabulary is **60**. The
[public API inventory](api-inventory.md) traces all 60 classes to production

reference lives on the dedicated pages: parameters, defaults, null policy,
failure behavior, examples, and replacement rules are documented in the
[Batch API reference](batch-api.md) and the
